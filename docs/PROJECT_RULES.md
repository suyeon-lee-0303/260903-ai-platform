# Project Goal
This is NOT a new project.
This is an existing working project.
Your task is to improve it.
Do NOT rebuild it.
Do NOT redesign it.
Do NOT migrate it.
---
# First Step
Before writing any code,
analyze the entire project.
Read
- index.html
- Code.gs
- docs/01_SPEC.md
- docs/02_PRD.md
- docs/03_UI_UX.md
Understand how everything works first.
Do not write code immediately.

# Existing Features
The following features already work correctly.
Keep all of them.
- Claude AI consultation
- Google Apps Script backend
- Google Sheets integration
- Free trial application form
- Mobile responsive layout
- Current UI design
- Current CSS
- Current JavaScript
These features must continue to work exactly as they do now.
---
# Development Strategy
Improve the current project.
Never replace the current project.
Work feature by feature.
Test each feature before continuing.
Make the smallest possible changes.
---
# Design Rules
Keep the current design.
Do NOT redesign the UI.
Do NOT replace CSS.
Reuse existing CSS classes whenever possible.
Keep
- Colors
- Fonts
- Buttons
- Card style
- Layout
- Mobile design
consistent.
---
# Code Rules
Do not delete working code.
Do not rename files unnecessarily.
Do not rewrite the project architecture.
Reuse existing JavaScript functions whenever possible.
Create new functions only when necessary.
Keep the code simple and readable.
Avoid unnecessary complexity.
---
# Backend Rules
Keep Google Apps Script.
Keep Google Sheets integration.
Keep Claude API integration.
Do not change the API flow unless absolutely necessary.
Do not expose API keys.
---
# Scope Rules
Implement only the requested feature.
Do not implement extra features.
Do not optimize unrelated code.
Do not refactor working code.
Stay focused on the current task.
---
# Feature Priority
Priority 1
AI Learning Recommendation
Priority 2
UI improvement (only if required)
Priority 3
Minor bug fixes
Everything else should wait.
---
# Error Prevention
Before changing any code,
identify
- where it is used
- what depends on it
- possible side effects
Never modify shared code without checking.
---
# Testing
After every change,
verify that
✓ AI consultation still works
✓ Claude API still responds
✓ Application form still works
✓ Google Sheets still receives data
✓ Mobile layout is still correct
Only then continue.

# Communication Rules
Before making significant changes,
explain
- what will change
- why
- which files will be modified
Never modify many files without explanation.
---
# Success Criteria
The project is successful if
- Existing features still work
- New feature works correctly
- UI remains consistent
- No regression occurs
- Code remains easy to maintain
---
# Final Rule
When in doubt,
preserve the existing project.
Adding one good feature is better than rewriting everything.
Always prefer small, safe improvements over large changes.
